# Render spike — genuine Excalidraw in a DSH client bundle

Question: can a DSH client plugin embed `@excalidraw/excalidraw@0.18.1` (the
real React component, not a reimplementation) and be interactively usable?

Short answer: yes. Verdict, measurements and risks:
[`docs/05-render-spike.md`](../../docs/05-render-spike.md).
Evidence: [`docs/evidence/render/`](../../docs/evidence/render/).

## Layout

```
src/standalone.js     React 19 page mounting Excalidraw (CSS + local fonts)
src/dsh-entry.js      DSH plugin module: inject/apply, tagged <style>, EXCALIDRAW_ASSET_PATH
src/module-table.js   page module table emulation with React 18.3.1 (live shell version)
public/               pages + harness (module loader facade, minimal slots renderer)
scripts/build.mjs     esbuild builds, size report, font/lazy asset copies
scripts/server.mjs    static server (/ faithful, /dsh-csp strict CSP, /dsh-lean lazy chunks)
scripts/ui-smoke.mjs  Playwright: mount, real drawing, API, exports, slot resize
scripts/dsh-loader-smoke.mjs  Playwright: __ModuleLoader__ contract, React 18, CSP and lean passes
scripts/canonical-elements.mjs  convertToExcalidrawElements + serializeAsJSON evidence
dsh-bundle/           spike copy of the DSH package (package.json, generated client.js, host font route)
artifacts/            screenshots + JSON evidence (regenerated by the scripts)
```

## Run

```bash
pnpm install --ignore-workspace --store-dir /Volumes/ZHITAI/DSHExcalidraw/.cache/pnpm-store
node scripts/build.mjs
node scripts/ui-smoke.mjs
node scripts/dsh-loader-smoke.mjs
node scripts/canonical-elements.mjs
node scripts/server.mjs          # manual: http://127.0.0.1:8787/ and /dsh
```

Requires Google Chrome at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`
(override with `CHROME_BIN`); no Playwright browser download is used.
