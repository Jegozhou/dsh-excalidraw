# 10 — Risks, license obligations, and the minimal evolution path

## 1. Risk register

| # | Risk | Impact | Likelihood | Mitigation / evidence |
|---|---|---|---|---|
| R1 | 8.0 MiB client bundle is fetched and parsed at every page boot | Slow first paint, memory pressure on low-end machines | Medium | Measured (8.01 MiB raw / 2.39 MiB gzip); spike proved a 4.67 MiB lean variant and a 0.70 MiB entry + 54 chunks are feasible. **v0.2 priority.** |
| R2 | Excalidraw is pinned to 0.18.1; a future version may change CSS, assets, React peer range, or element semantics | Renderer breakage on upgrade | Medium | Pin + E2E + golden corpus; upgrade is a deliberate change with the full verification suite. |
| R3 | Harness client-loader / tool / `connection` contracts are rc-versioned | Plugin fails to activate after a Harness update | Medium | Contract tests, E2E in an isolated profile, version note in the README; no speculative `engines.dsh` range. |
| R4 | Host-side text measurement is approximate | Agent-created text boxes differ slightly; bound text may reflow on open | Medium | Documented partial compatibility; Excalidraw re-measures; tests cover structure, not pixel equality. |
| R5 | No CRDT: concurrent element edits are not merged | A person's or agent's work is rejected/overwritten after confirmation | Medium | Optimistic revision fence, clear conflict UI with Reload/Overwrite, idempotent retries, hash evidence. |
| R6 | Cross-process lock is a file lock | Corrupted simultaneous writes on NFS/network filesystems | Low | Stale-lock recovery, per-name in-process queue, atomic rename, backups; documented limit. |
| R7 | Plugin code runs unsandboxed in the Host process | A compromised plugin can read/write beyond drawings | Low (this plugin is small and audited) | No arbitrary paths, no subprocess, no network calls, no eval; ~2.3k lines of original code; license/dependency audit. |
| R8 | Obsidian `.excalidraw.md` users cannot open their existing drawings | Adoption friction | High for Obsidian users | Explicitly documented; workaround is Excalidraw export to `.excalidraw`; importer is a candidate feature. |
| R9 | Font redistribution includes vendor-licensed binaries (Cascadia Code, Liberation Sans) | License compliance ambiguity | Low | Assets are unmodified from the MIT Excalidraw npm distribution; per-font embedded license metadata is recorded in `THIRD_PARTY_NOTICES.md`; no font is modified. |
| R10 | Upstream Obsidian plugin's AGPL/MIT contradiction | Legal ambiguity if any source were copied | Resolved for this repo | No upstream source copied; only facts and short quotations for evidence. The contradiction is documented, not "resolved". |
| R11 | React version split (page React 18.3.1, dev tooling React 19) | Type/runtime mismatch in development | Low | Client bundle externalizes React; the spike tested both 18.3.1 and 19.2.0; the shipped bundle was exercised in the live 18.3.1 page. |
| R12 | Excalidraw hardcodes an esm.sh font fallback | External request under a future strict CSP / offline network | Low | On the DSH page zero external requests were observed; local fonts load; CSP stress left 230 blocked attempts and 0 external responses. Patch/override if a CSP is introduced. |
| R13 | The live Desktop profile requires a restart to activate the installed bundle | User sees the plugin missing until restart | Certain, one-time | Recorded as `restart-required`; isolated instance proves the post-restart behavior; documented in the README. |
| R14 | No model credentials in the isolated profile, so the full LLM→tool loop was not run | The model-selection link is unverified | Medium | Tools were invoked through the real tool registry with the same execute path; the remaining link is Harness/LLM behavior, explicitly listed as unverified. |
| R15 | Test scenes/artifacts could leak into the package | Repository noise / install bloat | Low | Package `files` list excludes tests; `.gitignore` excludes `.tmp`, node_modules, spike builds; `lib/` and `assets/` are intentional. |

## 2. License obligations

### What this repository licenses

- **Original code** (`src/`, `build.mjs`, `scripts/`, `test/`, docs): MIT, see [`LICENSE`](../LICENSE).
- **Generated bundles** (`lib/index.js`, `lib/client.js`): contain original code plus the MIT-licensed Excalidraw renderer and its dependency closure; distributed under MIT with the notices below.
- **Assets** (`assets/fonts`, `assets/locales`, `assets/excalidraw.css`): copied unmodified from the MIT `@excalidraw/excalidraw@0.18.1` npm distribution. The CSS is rewritten only for absolute font URLs. Font binaries carry their own licenses (mostly SIL OFL 1.1; two vendor name-table variants are recorded).
- **Fixtures** (`fixtures/upstream/`): generated by the team with the MIT Excalidraw 0.18.145 runtime; provenance is recorded in the manifest. No file is copied from the AGPL Obsidian repository.

### What this repository does **not** do

- It does not copy, link against, or redistribute the AGPL `obsidian-excalidraw-plugin` source.
- It does not copy the `ea-scripts` collection (mostly unlicensed inside an AGPL repository, one archived icon with a commercial-font provenance).
- It does not resolve the upstream `LICENSE` (AGPL-3.0) vs `package.json` (MIT) contradiction. The audit records both and treats the source as AGPL for reuse purposes.
- It does not use the `@zsviczian/excalidraw` fork; the renderer is the upstream MIT package.

### Obligations we accept

1. Retain the Excalidraw MIT copyright and permission notice in [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).
2. Ship the font attribution/license table and the SIL OFL 1.1 text, since font binaries are redistributed.
3. Record the dependency license inventory and the unresolved `fuzzy@0.1.3` notice gap from the upstream audit as a known third-party question (it is not a direct dependency of this plugin's built bundle; see the audit for the closure analysis).
4. Do not imply that the Obsidian plugin's behavior or license is inherited by this original implementation.
5. If `.excalidraw.md` import is added later, it must be implemented from the format specification/own code, not by copying AGPL parser source.

## 3. Minimal evolution path

### v0.1.1 — hardening, no new surface

- Add a `request_id` to every UI save automatically (already implemented) and document the recovery workflow with screenshots.
- Add export-to-SVG/PNG using the already-bundled Excalidraw package exports (spike proved it works) if a user need is confirmed.
- Add a CI workflow running `scripts/verify.mjs` on Linux + macOS.
- Add a test for the lock stale-reclaim path (currently covered by code, not by an explicit test).

### v0.2 — boot cost

- Split the client bundle into a small entry + package-local `client.<name>.js` chunks loaded via `require.async`, following the render spike's split probe (0.70 MiB entry + 54 chunks). Re-run the 13-step E2E and measure boot time.
- Make `immediately: false` and load the editor only when the panel is opened, if the loader's slot registration permits deferral without an empty panel.
- Keep the single-file build as a documented fallback.

### v0.3 — Obsidian interop (only if demanded)

- Add an **import** path for `.excalidraw.md`: parse frontmatter, text/embedded sections and the JSON/compressed-json fence into our scene model. This is a format adapter, not a port of the Obsidian plugin; it must be implemented from the format description/own code.
- Add export to the Markdown envelope only if round-trip tests can prove structural equivalence for the supported subset.
- Keep `.excalidraw` as the canonical storage format.

### v0.4 — optional Obsidian backend

- Define a `SceneBackend` interface (`read`, `create`, `apply`, `list`) and implement the current file backend against it.
- A future Obsidian adapter can then be placed behind the same interface without changing tools or UI. It is explicitly **not** claimed in v0.1; it requires a runnable Obsidian environment and a separate verification suite.

### Deliberately not planned

Real-time collaboration/CRDT, OCR, PDF, Mermaid, a script marketplace, Obsidian note-graph integration, and encryption. Each would multiply the surface without serving the four core capabilities.

## 4. Decision checkpoints

Before any expansion, the following must remain true:

1. `scripts/verify.mjs` is green.
2. The 13-step E2E is green in a fresh isolated profile on the target Harness version.
3. The agent probe is green and its disk hash matches.
4. No new AGPL code or unresolved license enters the tree.
5. A new feature has a test that fails without it and a documented user need; otherwise it is rejected as scope creep.
